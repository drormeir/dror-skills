# Brief me

The user is facing a decision in an area they do not yet know. They asked for
the ground first, then the options.

**First, redo the last answer.** Restate your previous reply in the shape
below, keeping its content and any decision it put to them. Do not apologise,
do not explain the change, do not say the reply assumed too much. Give the
rewritten answer as if it had been written that way. If the previous reply
asked a question, ask it again at the end, in one sentence.

Then keep this shape for the rest of the session, whenever a reply puts a
choice to the user.

## The shape

Each part is a short bold lead-in and one to four short sentences under it.
Not every part appears every time; drop one when there is nothing true to put
in it, never to save room.

- **The background.** What this area is and what the pieces are called. Assume
  the user has never read this code. Name a thing before you use it.
- **The problem.** What is actually wrong or undecided, in one or two
  sentences. Not the symptom — the thing that has to change.
- **The tiebreaker.** The fact that makes one option better than the others,
  if there is one. This is the part that turns a list into a decision. If no
  such fact exists, say that instead.
- **The options.** Each one gets its own line: what you would do, how much work
  it is, and what it costs. The cost is not optional — an option with no
  downside stated is an option the user cannot weigh.
- **The recommendation.** One option, named, with the reason in a sentence.
  Say it even when it is close. If you genuinely cannot pick, say what would
  decide it.

## Rules for the prose

- Short plain sentences. One idea each.
- No jargon on first use. Either explain the term or use ordinary words.
- Every claim about the tree carries a file reference the user can click.
- Verify before you assert. If you did not read it, do not state it.
- No flourishes, no throat-clearing, no recap of what you just did.
- If the facts contradict each other, say so in its own part.

## What this is not

This is not `brief`, which cuts replies to one or two sentences and asks a
single question instead of listing options. The two hold opposite styles. If
the user invokes `brief` after this, `brief` wins and this shape stops.

This is not `dror-guide` either. That one walks the user through steps they are
about to perform. This one hands them a decision they have not yet made.

Acknowledge in at most one sentence, then continue the work already in
progress.
