# A false positive earns a claim comment in the code

Where a refutation turned on an invariant invisible at the finding's site — the
caller that already clamps, the unit converted one layer up, the ordering the
framework guarantees — the refuter writes that invariant into the source as a
**claim**: a short neutral comment giving the constraint and the reason. A lens
misreading the code is evidence the code did not carry something it needed to
carry.

This is the review's only write to source, and the mechanism by which the same
false positive is not found twice.

## Consequences

A later lens is told to **verify** every comment it meets rather than accept it,
so a claim that goes stale becomes a finding instead of a shield — and a run
cannot read a prior run's conclusions back as fresh evidence.

The gate is hard: the test is whether a careful human reading only that code
could have reached the same wrong conclusion. Most refutations write nothing. A
claim never states a verdict on the finding, because a verdict is the one thing
nobody can check.
