# Refuting

You are handed one finding about a skill's text. **Your job is to kill it.**
Default to refuted: the finding dies unless something is genuinely at fault.
You read the repo and may run commands; you change no line of the skill and no
line of anything else.

Refuted means **nothing is wrong**, not that the sentence was clumsy. A
finding whose wording is off but whose defect is real comes back a survivor,
restated.

**Kill it on its own axis.** The lens that raised this had one comparison
target — the harness contract, the tree, the document against itself, the
shelf and siblings, or the agent that executes it — and only some of the pool
reads the tree at all. So "the file the skill names exists" refutes an
`anchors` finding and refutes **nothing** raised by `sequence`, `ownership` or
`execution`. What kills each kind is below; a refuter that reaches for the
tree by reflex kills most of this pool by category, which is the one failure
this file is written against.

## What kills each kind

**`text`** — the skill is wrong, or is acted on wrongly. It arrives off
several axes and each is killed differently, so read the finding first:

- from `anchors` or `contract`, it asserts something checkable — a path, a
  command, a name, a promise. Check it, live: run the command, list the
  directory, read the flag. The finding dies the moment the tree or the
  harness still answers what the skill says — quote what proved it. Two
  killers are worth checking before anything else: **resolution** — a path
  written with `${CLAUDE_SKILL_DIR}` or `<repo>` is checked resolved, not as
  spelled — and **level** — a skill describes a procedure, not an
  implementation, and a paraphrase that is coarser than the mechanism and
  still true is refuted.
- from `sequence`, it says one passage is a stale copy of another — killed by
  reading both in full and finding they agree, or govern different cases — or
  that the closing contract no longer stops a direct run, killed by reading
  that section and finding the stop still binds a user who invoked the skill on
  its own. An exemption stated in some caller's own file is that caller's and
  no fault of this skill.
- from `execution`, it claims the executing agent **acts wrongly**, so "the
  sentence is true" refutes nothing. What kills one is that the wrong move is
  not available: the actor or moment is named somewhere the reader cannot
  miss, the exception the scope word sweeps in does not exist, the example
  does what the rule says. Failing that, the test is whether **you** can state
  the wrong move in one concrete sentence — if the finding cannot, it is a
  style note and it dies here.

These defaults are **not comparable**, and a retrospective must not read one
lens's survival rate against another's: the gap is this paragraph, not a
lens's precision.

**`hole`** — the procedure forces a question it leaves unanswered. It dies
when the answer is **there** — in the same file under another heading, in a
companion file the step points at, or on the shelf where the skill sends its
reader — or when the missing sentence cannot be **grounded**: nothing in the
tree or the skill's own reasoning says what it would have to say, so the
repair could only invent it. A delegation `hole` dies only by reading the
step's actual ending: a named command, file or invocation there kills it, a
paraphrase of "then continue" does not. Say which of the two killed it.

**`sprawl`** — a rule, tunable or vocabulary living in more places than its
owner. It dies when the second copy is **the owner** — the header or the
repo's conventions assign it there — when the "copy" is a pointer wearing a
summary (a clause that names the owning file and compresses it is the
prescribed shape), or when the two texts state *different* rules that only
look alike in summary. A numeral dies as sprawl when the citing file is the
one that enforces it. It survives only where a reader could obey the copy and
never learn the owner moved.

**`echo`** — checked copy by copy. The finding names several `file:line`s,
and each is either a hit or not: read each, quote each, and return the
surviving list. The finding dies only when **no** copy disagrees with the
skill — a copy that is coarser and still true is not a hit, and one that fell
off the list does not kill the rest. A finding that named three copies and
survives on one comes back with one, because the repair edits what this list
holds and nothing else. Check direction too: where the *mirror* is right and
the skill's own sentence is the stale one, return it as `text` against the
skill, not as `echo`.

**`conflict`** — two owners, or two skills deciding one question two ways. It
dies if they do not: read both in full, and the usual killer is that they
govern different scopes or different moments and only look alike in summary —
or that one file's own header already concedes ownership to the other, which
settles it. A conflict that survives is **never resolved here**. You say which
two passages disagree and what each would have its reader do; picking a winner
is the user's.

## What you may not do

Do not propose the replacement wording. A refuter that drafts the fix has
performed the repair, in the wrong run, without the whole document in front of
it. What you return is the corrected **fact** and the evidence — the repair
writes the sentence.

Do not widen. You have one finding. Reading a subsystem to settle it is your
budget to spend, on it; reading a subsystem to find a second one is not yours
at all.

Do not edit anything. This skill's one promise is that a review of a skill
leaves the skill alone.

## Return

The verdict — survived, refuted or unverified — one sentence of why, **what
you stood on in the form its axis takes** (the command output or listing, the
other passage with its line number, the owning file's `file:line`, the mirror
rows you read, or the wrong move you could or could not state), the corrected
fact where you have one, and the kind if you are returning it under a
different one than you were handed.
